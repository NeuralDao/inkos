# R5 — Русские метрики длины, заголовки глав и EPUB

**Дата:** 30.10.2026. **Статус:** статический аудит ЗАВЕРШЁН, код и тесты не изменены. **Проверенный коммит:** NeuralDao/inkos custom/main@3e2a4c7a15c0ecba7230e48ac26a8145798b9d82; последний интегрированный кодовой merge — 24bdd47c. Локальная feature-ветка Codex с P1.2a/b не проверялась. Основание: [ROADMAP](./ROADMAP.md) и [LANGUAGE_AUDIT](./LANGUAGE_AUDIT.md).

## Вывод

Для русской книги служебный язык EN и язык читательской прозы RU — разные параметры. Счёт длины, заголовок главы и EPUB должны следовать языку прозы; язык Auditor, Skills, runtime-state и форматы JSON не должны следовать счётчику слов. Нужны две узкие задачи Codex после P1.2b: **P1.3a — Unicode-счётчик и все его непосредственные потребители**; **P1.3b — сохранение/чтение номерных русских заголовков, экспорт и EPUB lang**.

**Предпочтение по реализации:** добавить явный режим **ru_words** при narrativeLanguage=ru, сохранить старую семантику en_words и zh_chars. Режим подсчёта не должен управлять выбором языка служебных промптов. Codex может выбрать более простой эквивалент лишь при доказанном сохранении этих контрактов. Не создавать новый общий языковой фреймворк.

**Узкие тестовые данные и критерии:** ненулевой подсчёт «Ведомость RiverLine лежала у причала», ё/Ё, латинские имена, цифры и индексы (например Apollo-1), дефис/тире, переносы, кавычки; Markdown frontmatter, numbered heading, fenced block — считать только прозу. Заранее документировать семантику дефисов/индексов и проверять её, не подгоняя счётчик под конкретный результат рассказа. Сквозная согласованность Writer → Settler → review → revise → index → word-sync; отсутствие случайного ZH-аудита и сохранение прежних EN/ZH результатов. Без платы и запуска тестов Codex по умолчанию.

## P1.3b: подтверждённые места

| Путь | Факт из исходников | Необходимое изменение |
| --- | --- | --- |
| packages/core/src/utils/chapter-document.ts | При служебном EN пишет заголовок # Chapter N: title; удаляет предыдущие номерные обёртки | Для RU-читателя один заголовок вида # Глава N: Название; не размножать при сохранении/ревизии |
| packages/core/src/utils/chapter-splitter.ts | Распознаёт Chapter N и китайские главы; «Глава N» не поддержана | Аккуратно добавить русский номерной разбор для повторного чтения и импорта, не принимая обычную прозу за заголовок |
| packages/core/src/agents/writer.ts и pipeline/runner.ts | Writer.saveChapter и ревизия не последней главы рендерят документ по операционному языку | Передать язык читательской обёртки, не затрагивая служебное состояние |
| packages/core/src/interaction/export-artifact.ts | Повторно оформляет заголовки по book.language; EPUB lang = en или zh-CN; totalWords берётся из индекса | Для narrativeLanguage=ru использовать RU в MD/TXT/EPUB и метаданных EPUB lang=ru; EN/ZH без регрессии |
| packages/core/src/agent/chapter-import-source.ts | Single-file импорт использует splitChapters | Экспортированный русский Markdown должен обратно разделяться на нужные главы |

**Тестовый контракт:** синтетическая книга с двумя главами «Обман RiverLine» и «Последний рейс»; save → reopen → revise → MD/TXT/EPUB → parse/split; ровно две главы в исходном порядке, сохранённое содержимое, не более одного номерного заголовка на главу, правильная кириллица и точное RiverLine. EPUB lang=ru проверять на реально созданном EPUB-файле без нового тестового сервиса; существующие EN/ZH-разборы должны сохраниться. Обычная фраза «Глава в этом деле...» не должна трактоваться как номер главы.
