## Точка продолжения именно исследований

- **Решение о границе проекта (30.10.2026):** R7a–R7b сохранить как архивные справочные материалы **без новых исследований коммерции, рынка, продвижения и площадок внутри InkOS**. Предполагаемый отдельный проект будет получать готовые черновики InkOS и выполнять функции помощника автора, независимого редактора/критика и продюсера, включая проверки правил и продаж. Этот проект пока не создавался, интеграция не проектировалась. Предварительные выводы R7b не заменяют проверку действующих договоров при реальной публикации; **R7 не является блокером G1**.
- **После G1 — R6(b) и калибровка R2/R4:** по сохранённым главам и фактической Selectel-telemetry оценить текст, причины дефектов, стоимость на принятую главу, reasoning, кэш и повторы. Не переписывать brief v1.0 задним числом; обновлять модели/гипотезы **по данным**, а не по рейтингу.
- **После G3/G4:** исследования накопления ошибок, целостности русского канона, читательского интереса и реальной работы длительного конвейера; запускать только при выявленном вопросе.
- **В любой момент по событию:** upstream-изменение, новая модель/прайс, фактическая несовместимость Selectel, подтверждённый дефект генерации или внутренней литературной ревизии. Уточнить один вопрос, проверить нужный код/источники, принять решение и обновить статус. **Изменения правил площадок** — забота отдельного будущего проекта, если они не создают прямое техническое требование к экспорту InkOS.
- **Точечный аудит P1.M проведён 30.10.2026:** по реальным семи исходным файлам `custom/main@fa2bff18` подтверждены риск неактуальной PiModel metadata при override, кэш клиента без ID модели, возврат usage только последнего structured turn, несовпадающие ключи `stateValidator`/`state-validator`, игнорирование отдельных настроек override без `baseUrl`. Прямые источники, ограничения и минимальные offline-критерии — [RESEARCH_R6_MODELS.md, раздел P1.M](./RESEARCH_R6_MODELS.md). **Это не означает runtime FAIL или проверку Selectel.** Все вопросы укладываются в уже существующую P1.M; новая исследовательская фаза, полный аудит 2.0 и отдельный LLM-proxy **не требуются**. R5/P1.3a/b не повторять без нового дефекта. Код P1.2b локально в GitHub не виден.

- **Аудит сборки контекста longform проведён 30.10.2026:** [раздел в R6(c)](./RESEARCH_R6_TOKEN_ECONOMY.md) по исходникам `custom/main@f7cbd6c`. Подтверждён дефект **коллизии чисто кириллических заголовков** в `Composer` с потерей следующих outline-разделов через `dedupeBySource` — приоритетное условие P1.6 (или раньше, если RU outline начнёт использоваться до него). При разных LLM-моделях **риск**, не проверенный runtime: Composer бюджетирует по собственному контекстному окну, а фактические потребители имеют другие окна; `selectTaskContext` и добавление предыдущей главы не пересчитывают этот бюджет. Есть явные защитные отказы при переполнении; не утверждать silent truncation. Подтверждённое дублирование memo и style guide в Writer пока **не даёт измеренной стоимости** и не оправдывает немедленного удаления. Узкий offline-кейс по моделям — в пределах P1.M, экономия — после G1. Исследование завершено; новую R-фазу и рефакторинг не открывать.

- **Решение по температурам G1 уточнено 30.10.2026:** [G1_MODEL_STACK.md](./G1_MODEL_STACK.md) документирует штатные per-call значения, параметры вызывающих ролей и ограничения транспортов. **Не менять эти значения и не разрабатывать тонкую настройку температуры для G1**: координатор должен знать встроенные профили; экспериментальная природа значений не подтверждена. В P1.M только проверить, принимает ли выбранный Selectel alias штатный параметр на реальном structured transport, и исправлять несовместимость узко, если она будет доказана. Баг `temperatureOverride=0` известен, но для базовой G1 не используется и не является блокером. Проверки и API не запускались.

## Разделение генератора и внешней редакции

**InkOS:** Writer/Reviser, канон, связность, русский текст, стоимость и воспроизводимость генерации; R2/R4 и G1–G4 оценивают сам генератор и не отменяются. **Отдельный будущий проект:** получает законченные черновики, проводит независимую читательскую редактуру/критику, формирует издательскую стратегию, исследует рынок, площадки, ссылки, маркетинг и продажи. Не переносить всю проверку качества из InkOS наружу: иначе дефекты Writer/Reviser останутся неизмеренными. Формат передачи материалов и автоматизация не утверждены, разработку интеграции не начинать.

## Границы и дисциплина перехода

**В исследовательском чате** можно читать код и публичные источники, работать с разрешёнными личными материалами, обосновывать решения и обновлять **только `fork-docs/`**. Не выполнять кодовую P1.2b, P1.3, P1.M, тесты, PR, Studio, платные API; команда «продолжаем» **не меняет режим**. После отдельного решения пользователя о возобновлении разработки использовать инженерный [CURRENT_STATE.md](./CURRENT_STATE.md), проверить реальную локальную ветку Codex. Не считать недоступные локальные файлы GitHub-данными.

**После полезного исследования:** вывод/факты/неопределённость и ссылка — в тематический документ и [RESEARCH.md](./RESEARCH.md) **по необходимости**; изменить **этот** файл, только если поменялись состояние, приоритет, триггер или главное решение. Держать текущий статус коротким, историю не переписывать. Код — всегда Codex, не ChatGPT. Платные API — только с разрешением и лимитом.
