## Точка продолжения именно исследований

- **R7b завершена (30.10.2026):** [RESEARCH_BOOSTY.md](./RESEARCH_BOOSTY.md) установила предварительно допустимую связку «бесплатная AI-маркированная книга AT + Boosty для ранних глав/бонусов», с ограничениями ссылок. **Перед реальными продажами** проверить полный договор Boosty, платёжные условия, возможные вопросы к ИИ-контенту, правила коммерческих ссылок AT и ценовой паритет/срок завершения по агентской оферте AT. Это **не блокер G1**, не подтверждение законности конкретной продажи и не прогноз дохода. Новые R-этапы ради паузы не открывать.
- **После G1 — R6(b) и калибровка R2/R4:** по сохранённым главам и фактической Selectel-telemetry оценить текст, причины дефектов, стоимость на принятую главу, reasoning, кэш и повторы. Не переписывать brief v1.0 задним числом; обновлять модели/гипотезы **по данным**, а не по рейтингу.
- **После G3/G4:** исследования накопления ошибок, целостности русского канона, читательского интереса и реальной работы длительного конвейера; запускать только при выявленном вопросе.
- **В любой момент по событию:** upstream-изменение, новая модель/прайс, фактическая несовместимость Selectel, новые требования площадки, подтверждённый дефект литературного качества. Уточнить один вопрос, проверить нужный код/источники, принять решение и обновить этот статус.
- **Проверка полезности дальнейшего статического аудита:** [R5](./RESEARCH_R5_LENGTH_EXPORT.md) уже ограничила P1.3a/b по непосредственным потребителям; [R6(a/c)](./RESEARCH_R6_MODELS.md) и [G1_MODEL_STACK](./G1_MODEL_STACK.md) описали P1.M. **Общий глубокий аудит всего InkOS 2.0 сейчас не нужен.** До передачи конкретного задания Codex можно сделать только короткую свежую сверку самых рискованных контрактов P1.M (фактически выбранный provider/model, PiModel metadata, tool calls, multi-turn usage, retries/abort) по настоящему кодовому HEAD; незакоммиченные локальные изменения Codex на GitHub не видны. Без новых свидетельств P1.3 заново не исследовать.

## Границы и дисциплина перехода

**В исследовательском чате** можно читать код и публичные источники, работать с разрешёнными личными материалами, обосновывать решения и обновлять **только `fork-docs/`**. Не выполнять кодовую P1.2b, P1.3, P1.M, тесты, PR, Studio, платные API; команда «продолжаем» **не меняет режим**. После отдельного решения пользователя о возобновлении разработки использовать инженерный [CURRENT_STATE.md](./CURRENT_STATE.md), проверить реальную локальную ветку Codex. Не считать недоступные локальные файлы GitHub-данными.

**После полезного исследования:** вывод/факты/неопределённость и ссылка — в тематический документ и [RESEARCH.md](./RESEARCH.md) **по необходимости**; изменить **этот** файл, только если поменялись состояние, приоритет, триггер или главное решение. Держать текущий статус коротким, историю не переписывать. Код — всегда Codex, не ChatGPT. Платные API — только с разрешением и лимитом.
