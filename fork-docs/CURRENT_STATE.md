## Обнаружено в коде 2.0

- TypeScript/pnpm-монорепозиторий: `packages/core`, `packages/cli`, `packages/studio`.
- Есть общий agent harness, 19 каталогов профессиональных Skills, Work-манифесты, поиск через SQLite FTS5, цепочка планирования, написания, ревью и сохранения состояния.
- Литературный аудитор — `ContinuityAuditor`; `agents/detector.ts` **не** литературный ревьюер, он вызывает внешние AI-детекторы.
- Per-agent `modelOverrides` **уже реализованы**; не планировать новый роутер без анализа существующего.
- **Русский язык читательской прозы ещё не реализован полностью.** После P1.1b `BookConfig` поддерживает необязательный `narrativeLanguage: en/zh/ru` и передаёт его через CLI/Studio/Work/Core; рабочий `language` остаётся `en/zh`. Writer/Reviewer/Reviser, Unicode-метрики, заголовки и экспорт пока не адаптированы для полноценной RU-генерации.
- **Направление P1:** английские внутренние промпты, Skills и служебные материалы сохраняем; русский художественный вывод реализуем точечно. Контракт языка P1.1b внедрён; Writer/Reviser и метрики — следующие P1.2/P1.3. Глобальный RU_SURFACE_CONTRACT не переносить.
- Историческое исправление 1.8: распознавание кириллицы в `inferLanguage()` позволяло избегать ошибочного маршрута `zh`; старого файла в 2.0 нет. В P1.1b явный RU-контракт направляет на операционный EN и отвергает `zh + ru`. Независимый риск `[A-Za-z0-9]` в счётчике глав и `englishWords` из `utils/source-text.ts` остаётся для P1.3; проверить потребителей `chapter-word-sync`, `runner`, `chapter-review`, `short-fiction`.
- Проведён углублённый статический аудит языковых контрактов 2.0: [LANGUAGE_AUDIT.md](./LANGUAGE_AUDIT.md) на историческом коммите `02756a4`. После аудита реализован P1.1b; **полный runtime-прогон русской литературной генерации, пользовательские Skills и платные API не проверены**.

- По коду на `custom/main@09aa5a17`: `resolveNarrativeLanguage` охватывает RU и допустимые явно выбранные EN/ZH, Writer возвращает `title/content` через `submit_chapter_draft`, а Settler вызывается отдельной фазой. `prepareWorkerMessages()` добавляет авторский запрос и Skills; проверять также эффективно собранные сообщения.
- Reviser выдаёт `submit_revised_chapter.revisedContent` либо `submit_chapter_range_replacements.range_N_content`: локальное исправление бывает с предварительным выбором строк и с прямым `targetText`, минующим выбор. В каждом случае текст вне разрешённых диапазонов сохраняется.
