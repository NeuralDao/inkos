# InkOS — навигация и источники рабочего контекста

**Репозиторий:** `NeuralDao/inkos`, рабочая ветка `custom/main`. **Цель:** качественная, интересная и экономичная **оригинальная русскоязычная литература**. Не развивать переводческий конвейер без отдельного запроса. Пользователь определяет цели, бюджет и разрешения; ChatGPT исследует, принимает решения и ревьюит; **только Codex меняет код**. ChatGPT самостоятельно ведёт **только `fork-docs/`**. Детали — [WORKFLOW.md](./WORKFLOW.md).

## Сначала определить задачу — два постоянных направления

| Вопрос пользователя | Прочитать сначала | Дальнейшее чтение |
| --- | --- | --- |
| **Исследовать** литературное качество, новые модели, стоимость, методику тестирования, публикацию, upstream-риски | **[RESEARCH_CURRENT_STATE.md](./RESEARCH_CURRENT_STATE.md)** | Только **один-два тематических** документа ниже; [RESEARCH.md](./RESEARCH.md) — если нужна история/полный исследовательский план |
| **Продолжить разработку**, проверить работу Codex, diff/PR или запланировать реализацию | **[CURRENT_STATE.md](./CURRENT_STATE.md)** | Нужный раздел [ROADMAP.md](./ROADMAP.md), нужный **код/коммит**, PR; детали из тематического аудита при необходимости |
| **Определить, что именно проверять в G1** | [G1_MODEL_STACK.md](./G1_MODEL_STACK.md) + [BENCHMARK_LONGFORM.md](./BENCHMARK_LONGFORM.md) | [RESEARCH_RU_RUBRIC.md](./RESEARCH_RU_RUBRIC.md); бюджет/код/платный запуск утверждать отдельно |
| **Вспомнить принятое решение или правило** | [DECISIONS.md](./DECISIONS.md) или [WORKFLOW.md](./WORKFLOW.md) | Исходный документ-обоснование только при необходимости |

**Проверять режим чата, а не искать «следующую задачу» в чужом контуре.** Пока пользователь не вернулся к ПК с Codex, **разработка на паузе**, исследования допустимы в режиме чтения/документации. «Продолжаем» в исследовательском чате не разрешает P1.2b, Codex или платный G1. Исследования — **постоянный цикл**: до G1 подготовка, после G1/G3/G4 анализ реальных результатов, при новых рисках/моделях/правилах — точечный новый проход. Это не отдельная Git-ветка и не обязательные исследования ради количества.

## Правила надёжности документации

1. **Актуальный статус — только в двух `*_CURRENT_STATE.md`.** Детальные отчёты, `RESEARCH.md`, `ROADMAP.md` и `DECISIONS.md` — источники фактов, зависимостей и истории, **не самостоятельные команды «сделать следующим»**. Пометки о дальнейших исследованиях внутри старых проходов относятся к **дате прохода**.
2. **Код важнее документации.** Перед техническими выводами проверять реальный код и commit **нужной** ветки. GitHub не показывает незакоммиченную работу Codex. Исторические фиксации версии 1.8, 2.0 и старые GitHub SHA нельзя выдавать за текущую реализацию.
3. **Краткое чтение по необходимости:** обычно этот INDEX + один CURRENT_STATE + один тематический документ. **Не индексировать все `fork-docs/` перед каждым ответом.** При возврате после перерыва проверить HEAD, статус, только нужные артефакты.
4. **Статусы не смешивать:** `аналитически завершено` ≠ реализовано ≠ локальные тесты PASS ≠ подтверждено платным API ≠ качество прозы принято. Исследования возвращаются при новом свидетельстве или после G1/G3/G4; не открывать новые R-номера автоматически.
5. **Без секретов и рукописей в публичном GitHub.** Исходные CSV Selectel, ключи, счёт/запросы и приватные главы остаются в личных источниках. В docs — выводы и ссылки, не персональные данные. **Не запускать платные API, тесты или CI без разрешения**; изменять код вправе только Codex.
