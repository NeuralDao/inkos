# InkOS — навигация и источники рабочего контекста

**Репозиторий:** `NeuralDao/inkos`, рабочая ветка `custom/main`. **Текущий API-провайдер для будущих проверок: OpenRouter (решение 31.10.2026; реальных вызовов ещё не было).** **Цель:** качественная, интересная и экономичная **оригинальная русскоязычная литература**. Не развивать переводческий конвейер без отдельного запроса. Пользователь определяет цели, бюджет и разрешения. **ВРЕМЕННЫЙ ПРИОРИТЕТ 31.10–04.11.2026:** ChatGPT пишет согласованный код/тесты **в отдельной task-ветке** и открывает **draft PR**, Codex независимо ревьюит/исправляет, пользователь отдельно решает merge. **После 04.11** вернуться к базовому режиму, если продление не согласовано. ChatGPT самостоятельно ведёт `fork-docs/`. Детали — [WORKFLOW.md](./WORKFLOW.md).

**Разделение обязанностей:** InkOS генерирует и проверяет собственный черновик (G1–G4); будущий отдельный проект принимает готовый черновик, независимо редактирует/критикует и занимается издательскими, рыночными и коммерческими решениями. **R7 — сохранённый архив; не развивать внутри InkOS.** Формат передачи и интеграция не утверждены.

**Проверять режим чата, а не искать «следующую задачу» в чужом контуре.** Разработка и исследование ведутся независимо; возвращение к ПК с Codex не означает автоматического разрешения на новую задачу. «Продолжаем» в исследовательском чате не разрешает P1.M, кодовые изменения или платный G1. Исследования — **постоянный цикл**: до G1 подготовка, после G1/G3/G4 анализ реальных результатов, при новых рисках/моделях/правилах — точечный новый проход. Это не отдельная Git-ветка и не обязательные исследования ради количества.

## Правила надёжности документации

1. **Актуальный статус — только в двух `*_CURRENT_STATE.md`.** Детальные отчёты, `RESEARCH.md`, `ROADMAP.md` и `DECISIONS.md` — источники фактов, зависимостей и истории, **не самостоятельные команды «сделать следующим»**. Пометки о дальнейших исследованиях внутри старых проходов относятся к **дате прохода**.
2. **Код важнее документации.** Перед техническими выводами проверять реальный код и commit **нужной** ветки. GitHub не показывает незакоммиченную работу Codex. Исторические фиксации версии 1.8, 2.0 и старые GitHub SHA нельзя выдавать за текущую реализацию.
3. **Краткое чтение по необходимости:** обычно этот INDEX + один CURRENT_STATE + один тематический документ. **Не индексировать все `fork-docs/` перед каждым ответом.** При возврате после перерыва проверить HEAD, статус, только нужные артефакты.
4. **Статусы не смешивать:** `аналитически завершено` ≠ реализовано ≠ локальные тесты PASS ≠ подтверждено платным API ≠ качество прозы принято. Исследования возвращаются при новом свидетельстве или после G1/G3/G4; не открывать новые R-номера автоматически.
5. **Без секретов и рукописей в публичном GitHub.** Исходные CSV Selectel, ключи, счёт/запросы и приватные главы остаются в личных источниках. В docs — выводы и ссылки, не персональные данные. **Не запускать платные API, тесты или CI без разрешения**; при активном временном режиме (31.10–04.11) ChatGPT меняет согласованный код **только в отдельной GitHub task-ветке**, а Codex проводит независимую проверку. После — базовое правило Codex.
