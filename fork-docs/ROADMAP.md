## P0 — воспроизводимая Windows-среда

**Цель:** один проверяемый способ разработки/запуска форка на Windows/pwsh, без потери исправлений при сборке.

1. Проверить и исправить конфликт настроек pnpm между локальным pnpm 12 и текущими `package.json`/`pnpm-workspace.yaml`, сохранив нужные dependency overrides и разрешения lifecycle-скриптов. Уточнить, какую версию pnpm использовать для форка.
2. Исправить dev-запуск Studio, чтобы корнем был выбранный проект книги, а не `../..` (путь до исходников); предпочтительна кроссплатформенная конфигурация без WSL2.
3. Выбрать безопасный запуск CLI из локальной сборки; отдельно оценить состояние зависимостей после прежнего `npm link`. Не предлагать массовый `pnpm install` без необходимости/согласия.
4. Для P0 согласовать короткую локальную проверку: версию CLI, корректный запуск Studio и API, минимальную проверку сборки. Наличие PASS — только по фактическому логу пользователя.

**CI на `custom/main`:** потенциально полезно, но не блокер для одиночного локального вайб-кодинга. Рассматривать отдельно как P2, поскольку сейчас используются локальные тесты.

## P1 — качественная русскоязычная литература

**Нативная поддержка `ru`, по частям, не монолитная «русификация»:**

- Пройти по реальным языковым контрактам проекта/книги/рабочего профиля. Определить совместимый формат `ru` и миграцию, избегая изменений существующих книг без отдельного разрешения.
- Сделать корректный подсчёт и ограничения объёма русского текста. Текущий `en_words` учитывает латиницу, а `zh_chars` использует символы без пробелов — ни один не является проверенным решением для русской прозы.
- Поддержать `ru` во входе/выходе Writer, Planner, ContinuityAuditor, Reviser и в требуемых промптах/Skills, сохранив проверку причинности и непротиворечивости.
- Обеспечить рабочий путь создания и написания книги через CLI; Studio UI локализовать только в необходимом объёме и не раньше базовой генерации.

**Оценка литературного результата:** подготовить небольшие сопоставимые примеры, критерии по естественности русского, темпу, диалогам, персонажам, клише, непротиворечивости и цене главы. **Платные эксперименты только по разрешению пользователя и с бюджетом.**

## P2 — экономичность и удобство

- **Не создавать ролевой роутер с нуля:** `ProjectConfigSchema.modelOverrides` и `PipelineRunner.resolveOverride` уже существуют. Изучить реальные ограничения, возможности per-agent reasoning/temperature и полноту учёта токенов; оптимизировать после измерений.
- Изучить фактический цикл `ContinuityAuditor` / `ReviserAgent`, частоту ревизий и расходы **на реальных примерах**, прежде чем менять пороги или поведение ревью.
- Оценить целесообразность CI для `custom/main` и расхождение pnpm 9 в workflow с локальным окружением. Без автоматического дорогостоящего тестирования по каждому коммиту.
- Удобство Studio/Windows по подтверждённым проблемам.

## P3 — идеи

- Полная русская локализация интерфейса Studio, если базовые сценарии уже работают и есть практическая потребность.
- Новые форматы литературы, интеграции и инфраструктура — только если доказана польза для главной цели.
