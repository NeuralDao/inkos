## Цель и границы

Историческая цель этого документа — техническая интеграция динамического бесплатного маршрута OpenRouter в InkOS. После последующего решения G1 использует **фиксированные бесплатные IDs** через `modelOverrides`; динамический `openrouter/free` — только exploratory. Сам этот документ описывает код интеграции и защитный режим, а не актуальный протокол отбора моделей. Литературная приёмка не подменяется транспортным smoke.

## Реализация

- Встроенный дефолт OpenRouter (`checkModel`) переключён с потенциально платного `openrouter/auto` на **`openrouter/free`**; явно выбранный `openrouter/auto` за пределами защитного режима остаётся допустимым. В модельный каталог добавлена карточка `openrouter/free`: **200K** контекст по описанию OpenRouter, **8192** — **локальный консервативный лимит вывода InkOS**, не гарантированный лимит всех исполнителей.
- **Transport не менялся:** остаётся `openai-responses` и существующий Pi/worker путь. Статический код поддерживает `tool_choice=required`, но совместимость случайного фактического исполнителя с tools/structured output, Responses SSE/reasoning и повторами требует локальной проверки и live preflight.
- **Опциональный предохранитель G1:** при `INKOS_OPENROUTER_FREE_ONLY=1` создание LLM-клиента, включая клиентов для агентных `modelOverrides`, отказывает при любом сервисе, кроме `openrouter`, неофициальном endpoint или модели, отличной от `openrouter/free`/`*:free`. Также отклоняются дополнительные поля `extra.models`, `extra.route`, `extra.plugins`, способные переопределить маршрутизацию/расходы. Ошибка до HTTP-запроса; другие обычные конфигурации при выключенном режиме не меняются.
- **Дополнительное статическое ревью (31.10):** в `chatCompletion(client, model)` обнаружен путь подмены модели без `clientWithModel`. В этом методе добавлена отдельная проверка **перед запросом**; `PipelineRunner` при активном free-only режиме **сразу в конструкторе** проверяет базовую модель и **все** `modelOverrides`, чтобы не начать создание книги с заранее неверной конфигурацией и не тратить бесплатную квоту до ошибки на поздней фазе. В Studio connectivity probe создание LLM-клиента перенесено внутрь существующего `try/catch`: отклонённый платный кандидат теперь должен давать обычный результат ошибки probe, а не необработанный отказ маршрута. Это статически обоснованные изменения, не доказательство успешной LLM-генерации.
- Добавлены проверки выбора бесплатного fallback, явной модели, Responses-метаданных, paid/auto/alternate-service и overrides, запрета дополнительного fallback и работы без флага. Дополнительные регрессии проверяют `chatCompletion()` с подменённым ID и `PipelineRunner`: разрешение бесплатных overrides и отказ на платных **в конструкторе, до API и создания Work**. Отдельный `openrouter-free-responses.test.ts` с поддельными Pi-событиями проверяет, что InkOS выставляет `tool_choice=required` для Responses и **не принимает обычный текст вместо обязательного tool call**. Последний тест не проверяет реальную сетевую сериализацию Pi SDK или поведение OpenRouter. **На момент написания этого раздела тесты ещё не запускались; фактические проверки и их SHA указаны в актуальном статусе выше.**

## Лимиты динамического исполнителя: протокол G1

**Проверенный код:** у `openrouter/free` в InkOS сейчас карточка **200K контекста** и **8192 токенов резервируемого вывода**, то есть известные InkOS лимиты **маршрутизатора**. Реальный `:free` исполнитель выбирается на стороне OpenRouter, может иметь **другие пределы контекста/выхода** и собственную квоту. **Локальная оценка входа — приблизительная**, учитывает промпт, историю и инструменты; она не гарантирует согласия токенизатора выбранной модели. Не заявлять, что 200K/8192 доступны любой бесплатной модели.

**Два новых офлайн-сценария в `openrouter-free-responses.test.ts`:**
1. Если локальный контекст + резерв вывода больше установленного лимита модели, InkOS должен отвергнуть запрос **до SDK/HTTP**, не обрезая авторский контекст.
2. Если upstream завершил structured-ответ по лимиту `length`, обвязка не должна передать недописанный tool call как успешный результат; завершение `length` должно остаться наблюдаемым.

**Оба сценария входят в четыре целевых файла, давшие 126 PASS на `09241c06`; после отдельного тестового typefix повторный Vitest не выполнялся.** Они не подтверждают отсутствие серверного `400`/`413` при более строгих лимитах выбранной модели. Нельзя решать такую ошибку только увеличением `contextWindow` в настройке.

**Исторический протокол динамического `openrouter/free`:** его preflight не является текущей квалификацией fixed IDs. Для активного G1 см. [G1_MODEL_STACK.md](./G1_MODEL_STACK.md): точные модели, in-memory overrides, free-only guard, synthetic fixture, ограничение логических попыток и отдельное разрешение на live API.

## Настройка на Windows (после ревью и отдельного разрешения)

В PowerShell **до запуска InkOS/Studio** в текущей сессии:

```powershell
$env:INKOS_OPENROUTER_FREE_ONLY = '1'
```

**Историческая конфигурация динамического smoke:** базовая модель `openrouter/free`. Для текущей fixed-ID qualification каждый override должен указывать точный разрешённый `:free` ID; `INKOS_OPENROUTER_FREE_ONLY=1` сохраняется. Секретный API-ключ хранить только локально; проверять effective-config процесса перед отправкой.

**Предохранитель не заменяет лимит расходов/бюджета на стороне OpenRouter** и не ограничивает число бесплатных запросов. Для исследовательского G1 установить отдельный минимальный лимит/ключ на стороне провайдера, проверить нулевые списания и действующие дневные ограничения. Без разрешения не выполнять API, даже если цена у модели $0.

## Критерии проверки Codex

Сначала независимый review GitHub diff и регрессионных тестов; исправлять лишь подтверждённые проблемы в той же ветке. Минимальные проверки **только после отдельного разрешения пользователя**, на синхронизированном, чистом Windows-репозитории **и без глобально включённого G1-флага**: отдельные новые тесты сами включают и выключают флаг через `vi.stubEnv`. Не запускать обычный набор Core тестов из той же PowerShell-сессии с `INKOS_OPENROUTER_FREE_ONLY=1` — этот режим намеренно блокирует тестовые модели других провайдеров.

```powershell
Remove-Item Env:INKOS_OPENROUTER_FREE_ONLY -ErrorAction SilentlyContinue
pnpm --filter @actalk/inkos-core exec vitest run src/__tests__/effective-llm-config.test.ts src/__tests__/provider.test.ts src/__tests__/pi-stream.test.ts src/__tests__/openrouter-free-responses.test.ts
pnpm --filter @actalk/inkos-core typecheck
pnpm --filter @actalk/inkos-studio typecheck
```

Это **предлагаемые команды, NOT RUN**, без `pnpm install` и без полного suite. Если разрешение распространяется только на один файл, сократить запуск. Затем (после отдельного API-разрешения) синтетический короткий live smoke на `openrouter/free`: обязательный tool call, валидные аргументы, provider model/response ID (или честный `UNKNOWN`), счётчик usage, контроль отсутствия расходов, ограниченный retry. При FAIL остановка, не переключаться на платную модель, документировать конкретную ошибку; для Responses `stream=false` в структурированных агентах пока возвращается к streaming — **не выдавать non-stream за проверенный**.
