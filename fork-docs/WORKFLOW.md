# Правила работы над InkOS

## Кто что делает

- **Пользователь:** формулирует цель, определяет приоритеты и бюджет; разрешает кодовую реализацию, интеграцию, публикацию, рисковые действия; запускает локальные проверки самостоятельно либо разрешает конкретные команды локальному Codex.
- **ChatGPT:** читает GitHub и код, анализирует, выбирает решение в границах цели, ведёт ROADMAP и `fork-docs/`, готовит задание Codex, независимо проверяет дифф и доказательства. Итог ревью — **ACCEPT / REVISE / REJECT**. Приёмка **не** разрешает merge.
- **Codex:** единственный редактирует исходники, тесты, зависимости, конфигурации, скрипты, CI. Сам решает мелкие детали; не расширяет согласованную задачу. Предъявляет дифф/коммит/PR и отчёт.

## Основной режим: локальный Codex + облачный ChatGPT

- **Codex Desktop на Windows** редактирует и проверяет локальный репозиторий `C:\Projects\inkos` по отдельной согласованной задаче. Codex Cloud и ChatGPT Work не являются обязательной частью цикла.
- **ChatGPT в обычном чате** читает GitHub (`custom/main`, рабочие ветки, коммиты, PR и `fork-docs/`) и материалы, явно переданные пользователем. Локальный `git status`, stash, логи и незакоммиченные файлы ChatGPT автоматически не видит.
- Для значимых изменений предпочитать рабочую ветку + PR в `custom/main`. Создание PR, push и merge требуют разрешения пользователя; **ACCEPT не равен разрешению на merge**.
- Генерируемые проекты и рукописи хранить отдельно от публичного репозитория. Не отправлять пользовательские данные и секреты в GitHub ради удобства ревью.
- **Локальные артефакты ревью** (patch, отчёты) сохранять вне репозитория и вне временных каталогов в `C:\\Projects\\inkos-review-artifacts\\<идентификатор-задачи>\\`. Для ревью незакоммиченных изменений передавать полный patch, включая untracked-файлы; ссылки `C:\\...\\` недоступны обычному ChatGPT — прикладывать файл. После push предпочтительнее PR в GitHub. Запись вне sandbox — только по точечному разрешению.

## Практический цикл

1. Пользователь описывает проблему или желаемое поведение.
2. ChatGPT исследует код **нужной ветки** и проверенный коммит, рекомендует минимальное решение, отмечает риски и критерии приёмки.
3. После согласия пользователя ChatGPT передаёт Codex задачу: **цель, границы, поведение, критерии приёмки**. Одного разрешения хватает на всю задачу.
4. Codex меняет только согласованное, проверяет дифф, перечисляет файлы, риски и **фактически выполненные** проверки.
5. ChatGPT предлагает минимально достаточные локальные команды **для Windows/pwsh**; пользователь выполняет их сам или поручает локальному Codex с явным разрешением. Отчёт содержит реальные PASS/FAIL и нужные строки лога.
6. ChatGPT делает независимое ревью. При REVISE возвращает узкое замечание Codex без нового масштабного рефакторинга; при ACCEPT рекомендует приёмку, но ждёт разрешения пользователя на интеграцию.
7. ChatGPT актуализирует `CURRENT_STATE.md`, `DECISIONS.md`, `ROADMAP.md` после значимых принятых изменений.

## Задачи, PR и планирование

- Мелкие исправления можно передавать Codex в чате без GitHub Issue.
- Для продолжительных/значимых задач Issue полезен как постоянная точка отсчёта. PR нужен для содержательного ревью, а не автоматически для каждого исправления.
- Codex Plan Mode — для межмодульной неопределённости, существенных рисков и сложных зависимостей; не повторять уже проведённый ChatGPT анализ.
- ROADMAP — ориентир, а не разрешение автоматически начинать новые задачи. Нет обязательных спринтов и сроков.

## Ограничения на тестирование

Без отдельного разрешения Codex **не запускает** `pnpm install`, build, test, lint, typecheck, E2E, Studio и повторяющиеся диагностические циклы. Разрешено читать и писать тесты в рамках задачи, анализировать код/дифф, рекомендовать команды.

Проверки выбираются по риску: обычно точечные; после группы изменений — по затронутым пакетам; полные — перед крупной интеграцией/релизом. Не объявлять тест PASS, если нет подтверждения. По FAIL — выяснить причину и дать точечное исправление.

## Работа с Git и данными

- Репозиторий: **NeuralDao/inkos**. Основная рабочая ветка — **custom/main**. `master` и `upstream-main` не загрязнять правками.
- Перед выводом проверить текущий commit/файлы GitHub; не считать локальную копию автоматически синхронизированной.
- Учитывать новые upstream-изменения, не применять их без анализа совместимости и разрешения.
- По умолчанию — только чтение. Не выполнять опасные команды, публикацию или платные LLM-эксперименты без явного согласия.
- **Не загружать** ключи, приватные рукописи и пользовательские рабочие данные в публичный репозиторий.

## Перенос контекста между чатами

Новый рабочий чат начинает с [INDEX.md](./INDEX.md) и [CURRENT_STATE.md](./CURRENT_STATE.md), затем читает связанные решения, ROADMAP, Issues/PR и нужный исходный код. Документация фиксирует только решения, факты, ограничения и следующий шаг; никакой стенограммы обсуждений.

ChatGPT может коммитить **только `fork-docs/`**, не меняя код, CI или другие файлы. Кодовая работа всегда через Codex.
